# AgentSpec on DeepSeek Harness (dsh)

> Port of AgentSpec to [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)
> (`dsh`), a Cordis-based agent harness where "everything is a plugin".

This is the third distribution of AgentSpec. It mirrors the Claude Code and
OpenAI Codex distributions but mounts AgentSpec's commands as **native dsh
plugins** (skills + human slash commands) inside a dsh profile.

| Distribution | Mechanism |
|---|---|
| Claude Code | `.claude/` slash commands + agents + KB domains |
| OpenAI Codex | `.codex/` + generated `source-command-*` skills |
| **DeepSeek Harness** | `plugin-dsh/` bundle: `ctx.skills` provider + `ctx.commands` |

## How it works

`plugin-dsh/` is a dsh **bundle** (npm package whose `package.json` declares
`dsh.bundle.patch`). When a profile stacks it, its `cordis.patch.yml` inserts
two plugin rows:

- **`agentspec-skills`** (`lib/skills.js`) — a `ctx.skills.registerProvider()`
  that serves all 49 bundled `SKILL.md` skills (the same `source-command-*` set
  Codex uses, plus `sdd-workflow`, `agent-router`, authoring and GitHub skills).
  The model invokes them through dsh's native `skill` tool, so typing
  `/brainstorm <idea>` or describing the work triggers the matching command.
- **`agentspec-commands`** (`lib/commands.js`) — `ctx.commands.register()` for
  the 17 core commands. Each handler reads the command's template, rewrites
  AgentSpec content references to the bundle's `assets/` root, and injects the
  result into the agent's next request via `agent.inject(createUserMessage(...))`.

Both plugins are plain ESM JavaScript (no build step) — valid for the Cordis
loader, which requires named `name`/`inject`/`apply` exports and no default
export.

## What runs

**Native slash commands (17):** `brainstorm`, `define`, `design`, `build`,
`continue`, `ship`, `iterate`, `create-pr`, `work`, `define-m`, `design-m`,
`status`, `memory`, `sync-context`, `readme-maker`, `meeting`, `build-slides`.

**Skills (49):** everything else — all remaining `source-command-*` commands
(data-engineering, review, knowledge, visual-explainer), `sdd-workflow`,
`agent-router`, `component-model`, `kb-build`, `github-cr-*`, `github-post-issue`,
`create-agent`, `create-skill`, `data-engineering-guide`, `visual-explainer`,
`meeting-analysis`, `standup-report`, `excalidraw-diagram`.

**SDD output** stays workspace-relative under `.claude/sdd/{features,reports,archive}`,
and generated documents are written in pt-BR — identical to the other
distributions.

## Install

Prereqs: DeepSeek Harness installed (`dsh`), a profile directory under
`$DSH_HOME/profiles/`.

```bash
# 1. Regenerate the bundle assets from .claude/ (single source of truth)
make dsh

# 2. Create a profile and stack the bundle
mkdir -p ~/.dsh/profiles/agentspec ~/.dsh/profiles/node_modules/@agentspec
ln -sfn "$(pwd)/plugin-dsh" ~/.dsh/profiles/node_modules/@agentspec/agentspec-dsh
ln -sfn ~/.dsh/profiles/node_modules plugin-dsh/node_modules   # resolve @deepseek-ai deps

cat > ~/.dsh/profiles/agentspec/package.json <<'EOF'
{
  "name": "dsh-profile-agentspec",
  "private": true,
  "dependencies": {},
  "dsh": { "profile": { "bundles": [
    "@deepseek-ai/dsh-base",
    "@deepseek-ai/dsh-web-app",
    "@agentspec/agentspec-dsh"
  ] } }
}
EOF
echo '[]' > ~/.dsh/profiles/agentspec/cordis.patch.yml

# 3. Run
dsh --profile agentspec --no-open --port 0
```

For a published/installed package use `dsh plugin add @agentspec/agentspec-dsh`
in the profile directory instead of the symlinks.

## Verify

```bash
make dsh-verify   # node plugin-dsh/verify.mjs — 49 skills + 17 commands
dsh --profile agentspec --dump-config   # confirm the agentspec rows compose
```

## Layout

```text
plugin-dsh/
├── package.json        # dsh.bundle.patch -> ./cordis.patch.yml
├── cordis.patch.yml    # inserts agentspec-skills + agentspec-commands
├── lib/skills.js       # ctx.skills provider over assets/skills
├── lib/commands.js     # ctx.commands handlers over assets/commands
├── assets/             # generated by scripts/generate-dsh-bundle.py
│   ├── skills/         # 49 SKILL.md bundles
│   ├── sdd/            # templates + WORKFLOW_CONTRACTS.yaml
│   ├── commands/       # flattened command templates
│   └── agents/workflow/
└── verify.mjs
```

## Regeneration

`scripts/generate-dsh-bundle.py` syncs `assets/` from `.claude/` (mirrors
`generate-codex-plugin.py`). `make dsh` regenerates; `make check` runs it in
`--check` (drift) mode. AgentSpec content changes land in `.claude/` and are
re-bundled with `make dsh`.

## Notes and limitations

- **No live model session in CI**: the port is verified by mounting both plugins
  in a real dsh profile (clean boot) and exercising the services directly
  (`verify.mjs`). End-to-end prompt execution needs a running dsh with a
  DeepSeek API key.
- **Plain JS over TypeScript**: chosen because the installed harness ships
  without `tsc`; the loader accepts ESM JS plugins. Type the plugins later by
  adding `@deepseek-ai/dsh-*` types if desired.
- **Content root**: command handlers resolve templates/contracts/agents from the
  bundle's own `assets/`, so no `CLAUDE_PLUGIN_ROOT` is required.
