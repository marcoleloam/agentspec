## Resumo

O Blackboard, introduzido no Build (v3.3.0), passa a cobrir o ciclo inteiro da feature (Brainstorm ao Ship). Um script stdlib determinístico (`memory-index.py`) lê Blackboards, arquivo (`archive/` + `MEMORY.md`) e gera resumos de entrada de fase (≤15 linhas), gates de bloqueio em perguntas abertas (🔴), e índice descartável para grep. Agentes registram trajetória (decisões, alternativas rejeitadas, premissas, mudanças de rumo) ao sair de cada fase; o SessionStart injeta as 5 últimas entradas. Sem dependências novas (stdlib Python 3 + Bash) e com compatibilidade retroativa para Blackboards antigos.

## Lições Aprendidas

### Processo

- **Captura automática de comportamento, não de lembrete:** A premissa A-001 ("agentes seguem a instrução de registrar") falhou na E2E inicial (2/4 fases). A-001 foi derrubada e mitigada via hooks do plugin (D-024…D-027), que tornaram a chamada determinística. Lição: disciplina em prompt exige validação E2E; se o passo é crítico, não deixe a LLM decidir se faz.
- **Perda silenciosa de dados é o pior modo de falha:** No E2E um agente escreveu `| ID |` em vez de `| # |` e 8 entradas sumiram sem aviso. Resultado: D-025 adicionou validação com exit 2 e saída ⚠. Lição: parser tolerante mas ruidoso vence parser mudo.
- **Merge com main (3.5.0) resolveu 5 conflitos via decisões estruturais:** A integração de `/eval` + phase routing no main (2026-09-24) trouxe 5 conflitos, mas o alinhamento em Decisões (D-008, D-010, D-014…D-016) facilitou a resolução. Lição: contrato estrutural escrito antes do código poupa retrabalho no merge.
- **Hooks do plugin cobrem a lacuna entre prompt e determinismo:** O fallback de 3 níveis de caminho para o script (D-026) + hooks validados no E2E resolvem o problem
a de agentes em ambientes diferentes (Claude Code, OMP, Codex, Grok, repo fonte). Lição: infraestrutura determinística reduz variância, mas hooks precisam de testes de ponta a ponta.

### Técnico

- **Stdlib Python 3 é suficiente para parser e índice:** Sem `toml`, `yaml` ou `re.MULTILINE` no Python < 3.11 a feature sai integrada no AgentSpec v3.3+. A decisão D-004 (sem dependências novas) simplificou distribuição nos 5 bundles (Claude Code, Codex, Grok, DeepSeek, repo).
- **Coluna `Fase` vence seção `Diário` para manutenção:** D-008 escolheu tabelas com coluna `Fase` em vez de seção única. Resultado: o dashboard (`status-dashboard.py`) segue intacto, parser é simples, agentes já sabem editar tabelas. Lição: extensibilidade vence restrutura.
- **Ranqueamento em faixas fixas resolve o problema do tamanho:** D-012/D-020 impõem 15 linhas com faixas em ordem (🔴 → 🟡 → decisões → lições). Resultado: teste `test_brief_caps_long_history_with_footer` garante previsibilidade; usuários veem o que bloqueia primeiro.
- **Domínios KB cascata cobre archive sem migração:** D-013/D-019 usam Blackboard metadata → DEFINE → varredura para localizar domínios. Resultado: AT-007 e `test_brief_includes_other_features_sharing_domain` validam memória entre features sem reescrever `archive/`.
- **Gate por script + prompt fallback é prático:** D-011/D-024 resolvem: script determinístico em Python, prompt em Bash/fallback. Resultado: bloqueio 🔴 Design→Build é garantido em Claude Code, e o agente sempre sabe o que esperar.

### Comunicação

- **Premissas marcadas explicitamente evitam suposições:** Cada premissa (`A-001`, `A-002`, etc.) no DEFINE foi validada ou deixada aberta. A-001 marcada como "❌ Derrubada" levou direto à iteração E2E. Lição: "não validado" é uma status tão honesto quanto "validado" se registrado cedo.
- **Bloqueio 🔴 só fecha com resposta humana:** D-027 resolve a crise onde um Design fechou uma pergunta por premissa (antes que o usuário respondesse). Regra agora explícita no Blackboard: "Append-only, só Status/Resolução mudam". Lição: regras visuais no artefato compartilhado evitam re-explicação.
- **Índice curto (≤15 linhas) reduz overhead cognitivo:** Agentes entram em `/define`, `/design`, `/build` com resumo pronto. Resultado: nenhum agente gastou tokens recarregando o histórico. Lição: compressão previsível de dados (index) vence leitura completa.

### Ferramentas e Bibliotecas

- **`importlib.util.spec_from_file_location` resolve o problema de imports hífen:** `memory-index.py` tem hífen (padrão do repositório), e Python 3 não importa módulos com hífen. A solução (usar `importlib` + `exec_module`) saiu em D-018 e é testada. Lição: nomes com hífen em Python devem estar cobertos em testes **de ponta a ponta** (import, uso, distribuição).
- **Regex header-driven evita parser state machine:** D-009 escolheu parser guiado pelos headers das tabelas (`| # |`, `| D |`, etc.) sem estado global. Resultado: compatibilidade retroativa com formatos antigos (com/sem acento, coluna `ID` acidental) e output `build --verbose` ajuda debug. Lição: parser stateless é mais robusto.
